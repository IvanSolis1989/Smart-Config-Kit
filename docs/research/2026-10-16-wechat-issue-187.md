It supplied no OS, client/configuration version, specific failing function, or connection logs. Its sole comment was an automated AI supplier-rejection message, not network diagnostic evidence. This record therefore establishes static false positives and the exact fix scope, not that these endpoints caused every part of the reporter’s failure. It cannot replace acceptance after the reporter reloads the new configuration. The maintainer’s local WeChat was neither inspected nor operated.

<a id="精确修复与验收合同"></a>
## Exact fix and acceptance contract

Add three exact `DOMAIN` exceptions to the existing `scki-adfp-direct` supplemental set and `rulesets/source/adfp-exceptions.json` registry, then synchronize clients through the authoritative generation chain. Do not add `DOMAIN-SUFFIX,weixin.qq.com` or move all Tencent domains or the entire WeChat process ahead of ad rules.

Existing native exact-domain formats were retained. On 2026-10-16, [Mihomo routing rules](https://wiki.metacubex.one/config/rules/) confirmed that `DOMAIN` means a complete-domain match. [Official rule-provider documentation](https://wiki.metacubex.one/config/rule-providers/) retains `domain`/`ipcidr`/`classical` behaviors and `yaml`/`text`/`mrs` formats, with MRS supporting domain/ipcidr. The three supplemental rules enter domain MRS through the existing generator, not as suffixes, keywords, or process rules. [Official sing-box routing rules](https://sing-box.sagernet.org/configuration/route/rule/) likewise distinguish exact `domain` from `domain_suffix`; generated output must retain the former. No new core fields or higher minimum versions were required.

Synchronization follows the existing one-way compilation chain:

| Consumer artifacts | Synchronization and exact-match acceptance |
| --- | --- |
| Clash Party Smart/Normal, CMFA, OpenClash Normal/Smart, FlClash | Generate the first fused domain MRS from the authoritative source, supplements, and registry. Clients retain the same fused-set reference rather than scattered main-rule edits. |
| Stash, Egern | Generate from synchronized CMFA using their respective generators. Stash retains compatible providers; Egern uses its own YAML sets, not direct Mihomo MRS URLs. |
| Shadowrocket, Surge, Loon, Quantumult X | Rebuild each first-segment native text set, retaining exact-domain semantics and DIRECT using existing formats rather than mechanically copying main-rule syntax. |
| SingBox Full (including clients consuming it directly) | Rebuild exact-domain arrays in fused JSON/SRS and check the first segment and DIRECT outbound. |
| v2rayN Xray, Passwall, Passwall2 | Existing fallback generators derive Xray rules or SRS references from the same fused assets; do not restore handwritten expanded inventories. |

These generation chains executed and passed static acceptance, not tests on every client device. Artifact versions and logs synchronized to v6.0.20. The fix does not suddenly make Windows process-name rules work on Android; earlier domain rules independently match these hosts.

<a id="android-应用排除依据与适用边界"></a>
## Android app-exclusion evidence and boundaries

On 2026-10-16, [official Mihomo TUN documentation](https://wiki.metacubex.one/config/inbound/tun/) confirmed that `exclude-package` excludes Android package names from TUN routing. Android user/app rules work only on Android and require `auto-route`. This is not Windows Clash Party process configuration, nor proof that GUI-managed VPNs consume YAML package lists.

[Android’s official `VpnService.Builder.addDisallowedApplication`](https://developer.android.com/reference/android/net/VpnService.Builder#addDisallowedApplication(java.lang.String)) (API 21 onward) states that excluded apps use the network as if the VPN were absent. Allow and exclude lists cannot coexist, and packages must correspond to installed apps. [Tencent MyApp’s WeChat page](https://sj.qq.com/appdetail/com.tencent.mm) identifies package `com.tencent.mm` and developer Shenzhen Tencent Computer Systems Co., Ltd. Cloned/multiple app instances and client implementations must still be checked against actual installed apps and GUI behavior.

Excluding WeChat on Android is therefore an optional whole-app bypass chosen by the user, moving the entire app outside VPN/TUN and exceeding these three domain exceptions. It is neither a prerequisite nor a default of this fix. No package exclusions, phone VPNs, or maintainer-local settings were changed, and the reporter was not assumed to use Android.
